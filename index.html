Skills, tools and a shared knowledge base that let any AI coding agent mod almost any PC game you own.
The agent finds the game, works out the engine and the route, reads the real code, builds the mod, makes art, 3D and sound with fal, tests it in the running game, cuts the video, and writes down what it learned for the next agent.

Coming next: the mod hub at universalmodder.com. Publish your mods, remix other people's, and make new ones.
Share what you make, get help, and follow along:

Install

Pick your agent. Each gets the same skills (Agent Skills format), the fal MCP server, and the um CLI.

AgentInstall
Claude Code/plugin marketplace add rehan-remade/universal-modder
/plugin install universal-modder@universal-modder
Codexcodex plugin marketplace add rehan-remade/universal-modder
codex plugin add universal-modder@universal-modder
Gemini CLIgemini extensions install https://github.com/rehan-remade/universal-modder
VS Code / CopilotEnable chat.plugins.enabled, run Chat: Install Plugin From Source, and enter this repo's URL
CursorCursor Marketplace, or clone (Cursor reads AGENTS.md and .cursor/mcp.json)
OpenCodeClone and run opencode inside it (opencode.json adds the skills and the fal MCP server)
or, on OpenCode 2, opencode plugin add 'github:rehan-remade/universal-modder#main::path:plugins/opencode' (the um tool and fal MCP; add the skills with Skills only)
Skills only
(any agent)		npx skills add https://github.com/rehan-remade/universal-modder
Anything elsegit clone https://github.com/rehan-remade/universal-modder and start your agent inside it

Inside a clone, each agent finds the skills where it looks for them: .agents/skills (Codex, Gemini CLI, Copilot, Cursor, OpenCode) and .claude/skills (Claude Code) are copies of skills/. Instructions are in AGENTS.md, which CLAUDE.md and GEMINI.md point to. MCP config is in .mcp.json, .codex/config.toml, .cursor/mcp.json, .vscode/mcp.json and opencode.json (which also points OpenCode at skills/).

Without a clone, OpenCode 2 installs the plugin in plugins/opencode/ with opencode plugin add: one um_run tool that passes its arguments straight to the CLI and runs um from PATH (see below), plus the fal MCP server when FAL_KEY is set and none is configured. A clone doesn't need it. See plugins/opencode/README.md.

The um CLI. The Claude Code plugin puts it on PATH (its SessionStart hook), and so does a clone opened in Claude Code (.claude/settings.json); in a clone with another agent, export PATH="$PWD/bin:$PATH". Other agents' plugin installs (Codex, Cursor, Gemini CLI, OpenCode) don't, so install it once:

uv tool install git+https://github.com/rehan-remade/universal-modder     # or: pipx install git+...

For assets, get a fal API key. It powers both the fal MCP server and um fal. Rather than exporting it from a shell profile or a .env, store it once with um fal key set: on Linux it goes into the desktop keyring (libsecret's secret-tool), elsewhere into an owner-only ~/.secrets/fal-key, and um fal finds it there (um fal key status shows which source is used). FAL_KEY in the environment still works and wins. The agent configs read FAL_KEY, so start your agent with it set; on Linux, take it from the keyring as below. With no key, fal's OAuth endpoint https://mcp.fal.ai/mcp-relay signs you in through the browser instead (fal's MCP guides), and um comfy makes images on a local ComfyUI server. um sprixen (2D sprites, animation sheets, tiles) uses Sprixen, a separate paid service with its own API key (um sprixen key set). um voidless (2D sprites, 8-way turns, animation sets) uses Voidless, also a separate paid service with its own API key (um voidless key set).

um fal key set                                                   # hidden prompt
export FAL_KEY="$(secret-tool lookup service fal.ai key api)"    # Linux: before starting the agent

You also need Git, Python 3.10+ and ffmpeg. uv is recommended. Blender is needed for 3D → sprite renders. Windows games are driven natively or from WSL.

The agent starts with the mod-any-game skill and runs the same loop every time:

  1. search the knowledge base;
  2. recon, then pick a route;
  3. set up a safe lab (saves backed up);
  4. read the actual code;
  5. build one working slice;
  6. generate assets;
  7. verify in the real game;
  8. record;
  9. package;
  10. write a field note for the next agent.

A knowledge base that AIs write for AIs

knowledge/ holds field notes: how specific games were actually modded, decompiled and reverse-engineered. Each note gives:

  • the exact versions that worked;
  • the route, and why;
  • what the engine really does;
  • how it was verified;
  • the gotchas (symptom → cause → fix).

Every agent that finishes a mod can open a pull request with its note, so the next agent starts where it left off instead of rediscovering the same traps.

um kb search "grand theft auto"                 # before you start: prior art (works outside the repo too)
um kb new --game "Hades II" --title "A new boon god" --from-scan hades --agent "Codex (gpt-6)"
um kb check knowledge/games/hades-ii/a-new-boon-god.md
um kb pr knowledge/games/hades-ii/a-new-boon-god.md --yes    # after your human says OK: branch, push, PR

Browse knowledge/INDEX.md. Every game is welcome. Contribution rules, for humans and AIs, are in CONTRIBUTING.md: no game files, no decompiled dumps, no cheating other players, and an honest status and verification.

Agents (agents/, subagent files with name + description frontmatter): a three-agent team for mods that take days. Claude Code loads them with the plugin; in a clone, start with claude --plugin-dir . --agent mod-orchestrator. Cursor plugins and Gemini CLI extensions read an agents/ folder too (untested here; Gemini CLI's subagents can't start other subagents). Three agents use several times the tokens of one, so keep it for long mods. What worked for one user: the orchestrator on Fable 5.1 at medium effort, the game worker on Sonnet 5.5 at medium, and the offline worker on Opus 5.5 at high. Any agent can read the files as role briefs.

AgentWhat it does
mod-orchestratorThe supervisor. Plans the work, runs the two workers, checks what they claim against logs and files, and reports to the human in plain language. Start it as the main session: claude --agent mod-orchestrator
mod-game-workerThe only agent that touches the running game: build, deploy, launch, probe, measure, fix
mod-offline-workerNever touches the game: studies SDK data, dumps and other mods, designs features, writes generators and patches, tests them against stubs, and hands over the exact live probes to run

Built with it

  • examples/terraria-tmodloader: Fal Arsenal for tModLoader.
    • Weapons: a homing missile launcher, a tactical nuke (crater + mushroom cloud), a chain-lightning rifle, a black-hole gun and an orbital strike.
    • Three new enemies and a two-phase Drone Mothership boss.
    • Every sprite came from fal.
  • examples/aoe2-de-civ: San Franciscans for Age of Empires II DE.
    • A new civilization with a Robotaxi unique unit and Delivery Drones, rendered from fal image-to-3D models at AoE2's camera angle.
    • A Transamerica Pyramid wonder.
    • A reverse-engineered .sld sprite writer.
  • examples/minecraft-gta5-passthrough: real Minecraft inside GTA V story mode.
    • A Fabric mod and a ScriptHookV + ReShade add-on exchange camera, ground and events over a local WebSocket.
    • Minecraft's colour + depth are depth-composited into GTA's frame.
    • Minecraft TNT, arrows and fireworks become GTA explosions and bullets, and Minecraft mobs fight the police.

Each has a field note with every non-obvious lesson: knowledge/INDEX.md.

Rules it follows

  • Any game you own: single-player, multiplayer, or servers you host. It refuses to inject into online games with anti-cheat, write cheats against other players, or bypass anti-cheat, DRM or ownership checks.
  • It never ships game files or decompiled code. Mods ship as code, your own assets, patches or converters.
  • It backs up before touching saves, and kills processes by PID only.
  • It asks before driving your mouse and keyboard, installing loaders into game folders, or publishing, PRs included.

Full reasoning: skills/mod-any-game/references/safety.md.
